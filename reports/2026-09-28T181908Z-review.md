For the 27 claims whose primary receipt sits on a blocked host (the GitHub REST API or a vendor site), the stored 2026-09-27 excerpt was reviewed and `fetched_at` stays 2026-09-27; those rows say so. New receipts were chosen from reachable primary sources only: the vendor's official GitHub organisation (README, CHANGELOG, model card or blog source file via raw.githubusercontent.com), PyPI and npm.
- Each claim now lists the assertions its text makes (`capability`, `availability`, `ownership`, `lifecycle`); each receipt lists what its excerpt evidences (`supports`). A claim is `supported` only if every assertion has a receipt whose excerpt, as fetched, supports it.
- Criteria: **availability** = the receipt shows the tool is published or offered now; **lifecycle** ("active", "maintained") = a release, upload, changelog entry or tag dated within 180 days of 2026-09-28 (on or after 2026-04-01), or the vendor saying it is actively developed; **capability** = the excerpt itself describes the function the claim names; **ownership** = the excerpt names the owner, developer or acquirer.
- Where a receipt did not support an assertion, a supporting receipt was added or the claim was narrowed to what the receipt says. No claim was widened. The layer a tool sits in is the map's editorial placement; where a claim used to restate the layer ("an agent memory option") and no receipt said so, the claim now says what the receipt says instead.
- The review hash binds each record to the claim text, tool, layer, status, owner, ownership event, assertions and every receipt's URL, snapshot hash and supports list. The next `drift snapshot` that changes an excerpt voids the review until a person reads it again.
